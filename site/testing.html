Coverage configuration

Node-only coverage through a small adapter.

vanilla-test.config.json runs test/coverage.js and includes server/*.js plus server/*.mjs. The dependency-free adapter discovers sorted *.test.js files, starts Node's native TAP reporter, and returns status, counts, and descriptions for all 33 tests. The configuration timeout is 120 seconds.

Line coverageGenerated from Ubuntu Node coverage. Function coverageGenerated from the same run. Branch coverageGenerated from the same run.
Node only: vanilla-test 2.1 validates only the selected target, so this project omits Chrome configuration entirely. Its project-owned reporter measures native V8 ranges from the shipped files without c8, source instrumentation, transpilation, or browser tooling.
Metric change: 2.1 measures V8 executable, function, and nested block ranges directly. These percentages are intentionally not compared with the former c8/Istanbul totals.
Gate behavior: a covered total can look healthy while one file falls below a threshold. Treat the failing per-file metric and its LCOV records as the work item.

Practical workflow

Add a focused regression test.

  1. Choose the owning test file.CLI behavior belongs in test/cli.test.js; configuration in test/config.test.js; server behavior in test/server.test.js. A new *.test.js file is discovered by both test and coverage paths.
  2. Build isolated state.Use OS temporary roots/ports and existing helpers. Do not add stored private keys or depend on a fixed local port.
  3. Assert the external contract.Check status, headers, body, lifecycle, emitted error, or CLI exit—not only an internal helper.
  4. Run the test directly.node --test test/server.test.js shortens the edit loop.
  5. Run the suite and coverage.Use npm test, then npm run coverage. Inspect any per-file gate failure.
  6. Finish with package smoke.npm run test:package catches missing exports/files and CLI packaging errors.

Coverage debugging

Turn a miss into one concrete branch.

  1. Open the primary report.Load coverage/node/index.html, then open the file named by the gate.
  2. Identify the exact miss.Use uncovered line/function/branch markers; do not chase the aggregate badge first.
  3. Confirm reachability and platform.Decide whether the branch is a supported contract, an error path, or a Windows-only guard.
  4. Add the smallest behavioral case.Trigger the public outcome and assert cleanup/error behavior as well as the happy path.
  5. Rerun targeted, then full coverage.Verify the new assertion, the per-file gate, and badge generation.
  6. Check root badge diff.On Ubuntu it should be intentional and committed. On Windows, do not commit platform-only endpoint drift.
